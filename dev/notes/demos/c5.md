# C5 Demo - Obsidian Ingest and Backlinks

## Purpose
Demonstrate PRD5 ingestion workflow:
- scan changed Obsidian notes
- extract structured items across idea/experiment/preproject/project/feature
- preserve source backlinks per item
- produce low-confidence review queue

## Exact Commands
Run:

```bash
make demo-c5
```

The target executes:

```bash
uv run python -m tools.workflow.obsidian_ingest.cli run \
  --note-root tests/fixtures/c5/obsidian/daily \
  --note-root tests/fixtures/c5/obsidian/preproject \
  --note-root tests/fixtures/c5/obsidian/workalongs \
  --note-root tests/fixtures/c5/obsidian/dumps \
  --force-full-scan
uv run python -m tools.workflow.obsidian_ingest.cli list --min-confidence 0.6
uv run python -m tools.workflow.obsidian_ingest.cli pending
```

## Expected Output
- `run` returns JSON with:
  - `run_id`
  - `notes_scanned`
  - `items_created`
  - `items_updated`
  - `low_confidence_items`
  - `duplicate_candidates`
- `list` prints item rows including:
  - `item_id`, `kind`, `title`
  - `confidence`
  - backlink refs count (`refs`)
- `pending` lists low-confidence items queued for review
- persistence files are written under:
  - `data/obsidian_ingest/`
  - `dev/notes/ecosystem/state/obsidian_ingest_state.json`

## Manual UX Walkthrough
1. Run `make demo-c5`.
2. Inspect ingest JSON and verify `notes_scanned` is non-zero.
3. Confirm list output contains mixed kinds (`feature`, `experiment`, `preproject`, `idea`).
4. Pick one item id from `list` and run `uv run python -m tools.workflow.obsidian_ingest.cli get <item_id>`.
5. Verify `source_refs` includes note path/title and excerpt so extraction is traceable.
6. Review `pending` output and approve one item with `uv run python -m tools.workflow.obsidian_ingest.cli approve <item_id>`.
