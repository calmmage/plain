# C4 Demo - Daily Feature Implementer

## Purpose
Demonstrate PRD4 daily automation cycle:
- build task candidate pool
- score and select one task with reasons
- pick execution workspace via deterministic policy
- enrich context from multiple sources
- generate review packet and execution log

## Exact Commands
Run:

```bash
make demo-c4
```

The target executes:

```bash
uv run python -m tools.workflow.daily_runner.cli score --task-source dev/notes/ecosystem/daily_inputs/tasks_sample.md --daily-budget 180
uv run python -m tools.workflow.daily_runner.cli run \
  --task-source dev/notes/ecosystem/daily_inputs/tasks_sample.md \
  --context-source dev/notes/ecosystem/daily_inputs/obsidian_context.md \
  --context-source dev/notes/ecosystem/daily_inputs/telegram_context.json \
  --context-source dev/notes/ecosystem/daily_inputs/bookmarks_context.json \
  --repo-path "$PWD" \
  --client codex \
  --changed-file src/plain/components/c4_daily_runner/service.py
```

## Expected Output
- `score` output lists candidate tasks ordered by score with reason tags.
- `run` output returns job payload fields:
  - `selected_task`
  - `workspace_type`
  - `workspace_path`
  - `client`
  - `session_id`
  - `changed_files`
  - `review_packet`
  - `execution_log`
  - `status`
- review packet file created in `dev/notes/ecosystem/review_packets/`
- execution log JSON created in `dev/notes/ecosystem/daily_runs/`

## Manual UX Walkthrough
1. Run `make demo-c4`.
2. Verify top-ranked task and scoring reasons in the score output.
3. Inspect JSON payload from `daily run` for selected workspace and session id.
4. Open generated review packet and confirm:
   - summary
   - changed files
   - run/test instructions
   - unresolved questions
5. Open execution log JSON and verify full score breakdown is persisted.
6. Confirm context included at least two source types.
